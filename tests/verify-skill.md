# 验证：FindMiss v0.1 行为验证 + 流程检查

## A. Skill 行为验证

### 1. 触发验证

```text
/findmiss 对比一下我的要求和实际交付
/fm 漏了什么
查遗漏
```

### 2. 输出行为验证

FindMiss 输出**必须包含**：

- [ ] 头部：`FindMiss · 比对 N 条要求，发现 M 处遗漏，K 个隐藏假设`
- [ ] ❌ 遗漏项必须有 `原始要求：` 原文引用
- [ ] ❌ 遗漏项必须有 `交付状态：` 说明未找到什么
- [ ] ❌ 遗漏项必须有 `影响范围：`
- [ ] ⚠️ 偏离项必须有 `原始要求：` + `实际交付：` 对比
- [ ] 🔶 隐藏假设必须指出 Agent 做了什么决定
- [ ] 🔶 隐藏假设必须有 `建议：` 让用户确认
- [ ] 💡 领域惯例标为"建议"而非"遗漏"
- [ ] 要求覆盖度表格（要求 × 状态）

### 3. 禁止项验证

输出**不得**包含：

- [ ] ❌ 规则代号（M-REQ、M-EDGE、M-ASSUME 等）
- [ ] ❌ 对代码质量的评判
- [ ] ❌ 对执行过程的评判（那是 FindAction 的事）
- [ ] ❌ 凭空发明用户没提的需求当作"遗漏"
- [ ] ❌ 替用户决定结果好不好
- [ ] ❌ 评分 / PASS / FAIL

### 4. 溯源验证

- [ ] 每条遗漏能追溯到原始要求中的具体句子
- [ ] 每条隐藏假设能指出 Agent 具体做了什么决定
- [ ] 领域惯例建议有明确的领域归属（安全/运维/通用）

### 5. 兼容触发验证

- [ ] `/findmiss` 能触发
- [ ] `/fm` 能触发
- [ ] `查遗漏` 能触发

## B. 流程检查

### 1. 版本验证

```bash
grep version skill/FindMiss.skill.md | head -1
# 应输出：version: "0.1.0"
```

### 2. 品牌验证

```bash
grep -c 'FindMiss' README.md
# 应 >= 5
```

### 3. 规则代号泄露检查

```bash
grep -E 'M-REQ|M-EDGE|M-CONSTRAINT|M-ASSUME|M-IMPLICIT|M-SCOPE' README.md
# 应无匹配
```
